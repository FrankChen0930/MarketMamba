# Obsidian Boundary

Obsidian is the project’s human history and discussion surface. Git-tracked `knowledge/` is the reviewed navigation layer. Machine contracts, tests, code, and immutable artifacts remain the technical authority.

The portable ownership/linking protocol is defined by [Obsidian Bridge](OBSIDIAN_BRIDGE.md).

## May live in Obsidian

- Decision history, meeting/discussion summaries, hypotheses, rejected alternatives.
- Personal working notes, questions, learning material, and long-form explanations.
- Links back to immutable commits, contracts, reports, and generated evidence.

## Must be promoted into Git to become current project knowledge

- Current semantic decisions, authority changes, subsystem boundaries, blockers, readiness gates, and operational state.
- New canonical artifact identities or deprecations.
- Rules that agents or maintainers are expected to follow.

Promotion means editing the appropriate project map/domain note and validating it in the same change. Copying a statement into Obsidian does not make it canonical.

## Must not be silently copied from Obsidian

- Credentials, private personal data, machine-local paths that expose secrets.
- Unverified runtime claims, inferred production state, or stale project summaries.
- Old experiment results reworded as current contracts or trading evidence.

## Historical rule

History explains why; it does not override the current project map or machine evidence. Preserve contradictions as dated context and resolve authority explicitly.
