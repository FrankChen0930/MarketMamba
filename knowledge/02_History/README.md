# Project History

This layer records why MarketMamba reached its current state. It is explanatory and historical, not a shortcut around current authority.

- Keep dated decisions, superseded approaches, and investigation narratives here or in the linked Obsidian vault.
- Link immutable commits, reports, and artifacts when possible.
- Mark obsolete claims as superseded; do not rewrite old evidence to match newer conclusions.
- Promote any current semantic/authority change into `knowledge/00_Project_Map/` and the relevant `knowledge/01_Domains/` note.

## Minimal structure

- `Decisions/` — material direction or contract decisions; use [DECISION_TEMPLATE.md](DECISION_TEMPLATE.md).
- `Experiments/` — human navigation for completed research; use [EXPERIMENT_TEMPLATE.md](EXPERIMENT_TEMPLATE.md).
- `Incidents/` — durable root-cause lessons and architecture consequences; use [INCIDENT_TEMPLATE.md](INCIDENT_TEMPLATE.md).
- `Milestones/` — concise project-level milestones when they aid navigation.

Do not create a decision record for every commit or copy machine artifacts into history.

For current truth, start with [Current State](../00_Project_Map/Current_State.md) and [Authority Map](../00_Project_Map/Authority_Map.md).
