# MarketMamba V7 integrated candidate

> **DATED HISTORICAL NOTE.** This 2026-09 research/design record is preserved for provenance. Its proposed work, environment and conclusions do not override the current project map or frozen corrected E5/E1 contracts.

Status: isolated candidate preparation. It is not an H1 result, measured performance, or an architecture promotion.

## Candidate and fixed protocol

The candidate retains the 59-column grouped factor embedding, zeros Group D (columns 48–59) without changing width, and applies a no-convolution Mamba-2 temporal layer. Temporal representations feed a V6-style GATv2 layer plus independent forward/reverse no-convolution Mamba-2 cross-stock paths. Bounded three-way fusion feeds the 5d/10d heads. The model contract is `(x, edge_index, edge_attr, padding_mask) -> (N, 2)`.

No-conv blocks retain projection/split, SiLU on x/B/C, injected official SSD, D skip, gate-before-RMS, output projection, inverse-softplus dt bias, and negative-exp A. `A_log`, `D`, and `dt_bias` are excluded from AdamW decay. `ngroups != 1` is rejected. There is no synthetic fallback.

Temporal valid positions are compacted in order, bucketed by sequence length, scanned once per bucket, and scattered back. Stocks are canonically sorted by `stock_id`; padded stocks never enter temporal, graph, cross-stock, loss, or metrics. Edges are filtered/remapped to the eligible canonical subset, and results retain original alignment through the preparation adapter.

The frozen protocol uses `Date`, `stock_id`, the literal V6 `FEATURE_GROUPS` order (15/20/12/12), `Alpha_5d`, and `Alpha_10d`. Its default is the original two-set protocol: training starts 2013-01-01 and removes the final 30 trading rows at the 2023-12-31 boundary; validation/evaluation is 2024-01-01 through the frozen comparison end 2026-06-02. Validation is not relabelled as an untouched test. An optional future test is accepted only when explicitly supplied, source-covered, and separated by another 30 trading rows. The frozen literal is validated through AST without importing the side-effectful V6 config. Training uses per-date rank-centered targets and frozen weights: 5d MSE 1, 10d MSE .5, 5d ListNet .5, 10d ListNet .25.

## Data and evaluation

`PreparedDataIndex` reads the prepared columns once, validates keys and finite active features, then discards the DataFrame after building per-stock sorted date/float32 feature/label arrays and a date-to-current-stock index. Train and validation share that one index. Each request performs one `searchsorted` per current-day eligible stock and slices only its chronological last 60 rows; it neither rescans full history nor constructs N×T×59 tensors for all dates. Labels retain NaN outside training while selected feature windows must be finite.

The `prepare` command reads the actual raw source directory and writes only to a new output directory. Restricted preparation keeps prices within the requested window but retains pre-window point-in-time fundamentals, revenue, dividend, cashflow, and macro context, with stock predicates on stock-keyed sources. Every stock/date-limited artifact is labeled diagnostic/restricted regardless of the flag. It reuses V6 `build_features(fundamentals_v2=True, availability_flags=False)` and `clean_and_scale(macro_norm="ts", neutralize="none")`, writes exact 59D Parquet, raw economic prices, source hashes/health, two-set splits, and converts only `knowledge_graph_v2.npz` edge arrays to validated CSR with `allow_pickle=False`. `knowledge_graph_cache.npz` and the normalized 66D baseline cache are prohibited substitutes. The source audit preserves sparse/special-trading-day disclosures and calendar union. Any selected ordinary-stock OHLC contradiction, duplicate key, invalid price, missing active feature, graph mismatch, or purge failure blocks preparation. Group D remains deliberately zeroed, so inactive macro12 freshness is not required; valid TWII coverage through selected prices is required because RS features remain active.

Predictive evaluation compares candidate scores with a future supplied frozen `v2_kg_nomacro` checkpoint/score file on identical evaluation keys; no local baseline weights exist and no comparison claim is made now. Economic replay accepts naturally ragged daily score panels, leaves absent scores as NaN, uses all market trading dates in the scoring interval, and maps rebalances only to score-bearing frequency dates. It rejects duplicates, nonfinite scores/prices, nonpositive Close, and missing scored-stock prices. Columns are lexically sorted and ranked exactly like V6 (`method="first", ascending=False`). The unmodified `portfolio_lab.run_config` receives N=50, buffer=1.5, frequency=20, equal weights, and its 0.0015 buy/0.0045 sell costs; normalized feature Close is never used as an economic price.

Train, smoke, and forecast accept the same explicit `--runtime-metadata` JSON parser as the standalone probe. A synthetic metadata/wheel fixture match establishes manifest selection and checksum behavior only; it is not evidence of an installed wheel, successful import, real Mamba-2 execution, CUDA, or GPU compatibility.

Checkpoints include configuration, model-source/runtime, feature/KG/data/split fingerprints, RNG, optimizer/scheduler state, and exact next epoch/batch/step. A neighboring runtime JSON is persisted. Resume rejects mismatches and performs no update past its budget. `smoke` uses its own explicit short cap and checkpoint. Full `train` computes `epochs × train_dates` when `--max-steps` is omitted, emits bounded JSON progress, saves to persistent storage every configurable 100 updates plus epoch/end/cap boundaries, and chooses `.best` only from validation.

## Evidence boundary

Local verification is limited to project-venv CPU tests with explicit synthetic SSD injection and mocked CUDA detection. Official SSD/GPU execution, full prepared-data validation, training, and performance remain pending future Colab execution.
