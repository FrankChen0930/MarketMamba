## 二、待決策事項（最高優先，建議先在 plan mode 討論這兩項，其餘檢核單項目才有意義往下走）

### 決策1｜特徵可得期間異質性（Feature Availability Heterogeneity）

背景：不同特徵組的歷史起點不同（價量2005年起、法人籌碼2018年起、當沖2014年起），同一支股票同一天，不同特徵組的「有沒有意義」不一樣。

| 選項 | 做法 | 優點 | 代價 |
|---|---|---|---|
| A. 切齊訓練起點 | 訓練集只用「所有特徵組都齊全」之後的資料（例如2018年起） | 最乾淨、不用改架構 | 丟掉2005-2018長歷史，Mamba的長序列優勢用不上 |
| B. 缺失標記＋允許訓練集有缺 | 擴充 `padding_mask`，除了「序列長度不足」，也標記「這一欄是補出來的」，讓模型自己學會不同時期的可信度 | 保留全部歷史 | 需要改動訓練端的 mask 邏輯，工程量較大 |
| C. 分階段/分組訓練 | 早期只用核心價量特徵，晚期才餵入法人籌碼類特徵 | 折衷 | 概念上接近 curriculum learning，複雜度介於A/B之間 |

- [ ] 決定選哪一個（或哪個混合方案）
- [ ] 若選 B 或 C，`padding_mask` 的擴充範圍要明確定義：哪些特徵組需要 mask、mask 的粒度是逐特徵還是逐特徵組
- [ ] 決策結果是否要寫進 `fundamentals_v2`（或新開一個版本旗標），供之後追蹤

### 決策2｜GATv2 圖結構建構方式

背景：Mamba 處理個股時序，GATv2 處理股票間關係，但「誰跟誰連邊」需要明確設計，資料處理完不會自動生成。

| 選項 | 做法 | 優點 | 代價 |
|---|---|---|---|
| A. 產業分類建圖（static） | 同產業股票連邊，用 `stock_info` 產業分類 | 穩定、可解釋、資料現成 | 忽略跨產業但基本面連動的關係 |
| B. 動態相關性建圖 | 回看窗口報酬相關係數超過門檻即連邊，定期重算 | 能捕捉動態關聯 | 計算量隨股票數平方成長（~2900檔規模下需注意）；相關性本身也可能是巧合（多重比較風險） |
| C. 混合式 | 產業關係當基礎邊，動態相關性做權重調整 | 兼顧穩定與動態 | 工程複雜度最高 |

- [ ] 決定選哪一個
- [ ] 若涉及動態相關性計算，是否需要稀疏化機制（如只保留 top-k 邊），避免計算複雜度蓋掉 Mamba 省下來的效能
- [ ] 圖結構本身是否需要 point-in-time（產業分類是否曾經變更、公司關係是否隨時間改變），還是先接受用現況快照
- [ ] 是否需要對「用相關性建圖挑出來的邊」做顯著性檢驗（避免巧合連邊），還是先用固定門檻起手、之後再評估

## 三、特徵工程檢核單（決策拍板後逐項核對）

### A. 橫斷面處理順序
- [ ] 每個新增特徵是否都先在各股時間序列上算完，才做橫斷面標準化（沿用資料層已驗證的順序原則）
- [ ] 是否有例行化的子集不變性測試（縮小宇宙、比對數值逐位元一致），可以在每次新增特徵時自動跑一次，而不是靠人工複查

### B. 產業／市值中性化
- [ ] 中性化用的產業分類來源是否 point-in-time，還是用現況快照回推歷史
- [ ] 中性化統計量（每產業當日均值/標準差）是否只用當天實際可得的股票池計算
- [ ] 中性化前是否已排除 ETF／興櫃股（資料層已處理，確認有沒有正確傳遞到特徵層）

### C. 缺失特徵處理（對應決策1的具體實作）
- [ ] 依決策1選定的方案，`padding_mask` 或等效機制是否已對應實作
- [ ] 缺失標記是否會被誤當成真實的 0 值（呼應資料層 A6「補值未標記為缺失」同一類問題在特徵層的版本）

### D. Walk-forward／CV 切分下的特徵一致性
- [ ] Purged K-Fold + Embargo 的切分邊界，是否有考慮到「某些 fold 落在特徵可得期間之前」的情況（例如切到2010年以前的 fold，法人籌碼類特徵全缺，這個 fold 的訓練意義需要重新評估）
- [ ] 決策1若選A（切齊訓練起點），CV 切分範圍是否已同步調整

### E. GATv2 圖結構具體實作（對應決策2）
- [ ] 邊的計算複雜度隨股票數增加的量級是否在可接受範圍
- [ ] 若採動態相關性建圖，稀疏化機制是否已到位
- [ ] 圖結構更新頻率（每天/每週/每月重算）與計算成本的取捨是否已評估

### F. 凍結時間點原則（重申資料層原則到特徵層）
- [ ] 去極值門檻、z-score 用的統計量，是否僅用「當下時間點為止」可得的歷史計算，沒有用到全樣本一次算好套用到所有歷史時間點

## 四、建議帶去 plan mode 的討論順序

1. 先過一遍「一、前置確認」，確保資料層交接沒有漏掉的東西
2. 決策1、決策2 是這份文件的核心，建議先討論完這兩項，再進入檢核單逐項核對
3. 檢核單 A、F 兩類（橫斷面順序、凍結時間點）本質是資料層已經驗證過的原則，只是要確認新增的特徵工程程式碼有沒有繼續遵守，可以請 Claude Code 直接沿用資料層那套驗證方法（子集不變性測試）
4. 檢核單 B、C、D、E 則是這階段真正的新工作，需要跟決策1、2的結果對齊
