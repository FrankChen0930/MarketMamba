# MarketMamba 風控層基本版檢核表

> 用途：模型訓練階段（F6及後續）用的「通用基本版」風控參數，
> 與《組合建構基本版檢核表》搭配使用——組合建構決定「錢怎麼分」，
> 這份決定「什麼情況下要踩煞車、什麼情況下要先確認再動」。
> 明確不是最終規格，是微調前的共同基準線。
> 對應課程：階段B延伸「組合建構＋風控層」（7/14）、「多因子風險模型與風險歸因」（7/24）。

---

## A. 部位與曝險限制

- [ ] **單一個股上限**：即使等權配置理論上每檔都是1/50=2%，仍建議設一個硬上限（如單股不超過組合5%）作為保護——當有股票下市/停牌導致無法賣出、部位卻沒被替換掉時，該部位占比可能被動升高，需要有上限擋住
- [ ] **單一產業上限**：基本版建議設一個寬鬆的警戒值（如單產業不超過組合40%），不強制執行、但要能被監測到——目的是及早發現「模型排序意外集中到某個產業」，這種集中可能代表模型在搭某個產業的順風車，而不是真的選股能力（呼應7/24課程「alpha是真本事還是搭了因子順風車」的警覺）
- [ ] 觸及上限時的處理規則是否明確（等比例縮減超額部位？還是暫停該股票的新增部位、讓其自然淡出？基本版建議選後者，較簡單、對既有部位干擾小）

## B. 波動與回撤：基本監控（非動態控制）

- [ ] **基本版不做動態波動目標調整**（依7/14課程，這是進階功能，留到模型規格穩定後再加）——但**必須要有波動度的基本報告**：組合的滾動波動度（如20日年化波動）要出現在每次回測/推論報告裡，不能只看報酬數字
- [ ] **最大回撤（MDD）必須是每次報告的固定項目**，不是選配——單獨看年化報酬容易忽略「賺得穩不穩」，MDD是最基本的穩定度指標
- [ ] 是否記錄「回撤持續期間」（從高點到回補所需天數），這個資訊在判斷「一次正常的波動」跟「策略可能開始失效」時，比單看MDD數字更有參考價值
- [ ] 基本版建議設一個**觀察型（非自動執行）的回撤警戒線**（如淨值回撤達15%時，觸發人工檢視而非自動減碼）——先建立「知道要看」的習慣，動態自動降風險留到之後

## C. 台股特殊執行風險

- [ ] **漲跌停鎖死導致無法出場**：組合裡若有股票在再平衡當天觸及跌停鎖死，理論上該賣出卻賣不掉，回測時是否有正確模擬這個限制（而不是假設永遠能以收盤價成交）？如果沒有模擬，回測報酬可能被高估
- [ ] **持有期間股票被列為處置股/注意股/全額交割股**：若買進時正常、持有期間狀態轉變，基本版至少要能偵測到這個狀態變化並記錄，即使暫時不主動處理（處置股常伴隨交易限制，可能連帶影響能否如期出場）
- [ ] **持有期間下市**：需要一個明確、簡單的處理規則（例如以下市前最後成交價認列損益，或以0處理），並且這個假設要清楚寫在回測報告裡——不同假設會顯著影響年化數字，讀報告的人需要知道用的是哪一種
- [ ] 除權息事件是否正確反映在回測的報酬計算裡（用還原股價計算報酬，這部分你們資料層已經處理過，這裡是確認組合層的回測邏輯有沒有正確銜接還原後的價格序列，沒有各自維護一套不同步的邏輯）

## D. 執行前健康檢查閘門（Pre-Trade Sanity Gate）

這一類是你們過去幾週資料/特徵管線踩過的坑，在「執行」這一層的對應版本——**目的是在每次再平衡/推論執行前，先確認今天的輸入資料本身沒有異常，而不是盲目相信模型輸出**：

- [ ] 當日納入排序的股票數量，是否有覆蓋率檢查（跟資料層`hygiene.py`的邏輯一致：單日股票數變動超過某個百分比就示警，而不是靜默接受）
- [ ] 當日模型輸出的分數分布，是否有基本健檢（例如分數是否呈現合理的分散度，而不是大量重複值或全部接近0——這種退化分布可能代表上游某個特徵管線悄悄壞掉了）
- [ ] Macro/總經類特徵（Group D）若停更，是否會在推論前被偵測到並示警，而不是讓模型悄悄吃到過期資料
- [ ] 這個健檢閘門的判定結果，是否會被記錄下來（即使當天沒有觸發示警，也要留存「今天檢查過、結果正常」的紀錄，方便之後回頭追溯任何異常的起點）

## E. 模型/訊號失效監控（輕量版，非正式風險歸因）

- [ ] 是否有追蹤Rank IC的**滾動狀態**（例如過去20/60日的滾動IC），而不是只看單一整段回測期間的平均值——滾動IC能更早發現訊號是否開始系統性衰退
- [ ] 是否記錄每次再平衡的**周轉率**，並觀察其是否穩定——周轉率若無預警大幅上升，可能代表模型排序變得不穩定（呼應7/14課程「排序的日對日穩定性本身值得監控」）
- [ ] 基本版不需要做完整的因子暴露分解（MCTR、風險歸因），但建議至少手動抽查：組合目前主要持股，是否明顯集中在某個容易辨認的主題/類股（例如全部是AI相關、全部是航運股），作為「有沒有搭到單一敘事順風車」的簡易人工檢查

## F. 事件記錄與異常回報

- [ ] 每次再平衡的完整決策紀錄是否有留存（當天股票池、分數、選中的50檔、觸發的任何警示），確保之後回頭追查問題時有跡可循，不用重新回推
- [ ] 任何一項健檢（C、D、E類）觸發異常時，是否有明確的「這次要不要照常執行再平衡」的判斷規則，而不是臨場決定——基本版建議：異常若發生在**資料層**（覆蓋率、分數分布退化）就暫停當次再平衡並人工檢視；異常若發生在**個股層**（單一股票漲跌停、處置狀態）則正常執行、只排除該檔

## G. 通用版 vs 專屬微調：邊界說明

以下項目**明確排除在基本版之外**，等最終模型規格定案、且對模型的實際表現特性有足夠認識後才處理：

- 動態波動目標（volatility targeting）的實際調倉機制
- 自動化的回撤降風險觸發（現階段只做觀察型警戒，不自動執行）
- 完整的MCTR風險歸因與因子暴露分解
- Long-short部位下的beta neutral動態調整
- Core-satellite架構下，satellite（Conviction子集）的獨立風控參數（例如更嚴格的單股上限）

## 使用建議
這份檢核表跟《組合建構基本版檢核表》一起讀：組合建構決定「配置規則」，這份決定「什麼時候該停下來看一眼、什麼情況要有預先講好的處理方式」。兩份合起來，才能讓F6之後產出的每一批年化數字，都是在同一套「執行紀律」下產生的，之後好壞的比較才有意義。D類「執行前健康檢查閘門」是這份清單裡最值得優先落實的一類——**你們過去幾週在資料層抓到的每一個「安靜出錯」的問題，都證明了『先確認輸入正常,再信任輸出』這件事的價值，這個原則不該只停留在資料處理階段，執行層一樣需要**。
