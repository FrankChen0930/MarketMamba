## 0. 為什麼要做這件事（動機的量化依據）

現行口徑（Top50 等權、5 日再平衡、無緩衝）實測換手 **70–77%／次**：

```
每次成本 = 0.71 × 0.15%(買) + 0.71 × 0.45%(賣) = 0.426%
每年 252/5 = 50.4 次  →  複利後年化成本拖累 ≈ 19.4%
```

而 `v2_kg` 的**淨**年化只有 **+8.3%** → 毛報酬約 +28%，**被成本吃掉的比留下的還多**。

這個數字有獨立驗證：D4 測「成本 ×2」時 Ridge 從 +18.7% 掉到 −5.4%，
差 **20.3 個百分點**，與上面算出的 ~20% 幾乎完全吻合。

→ **一個能把換手砍半的設計約值 +10 個百分點年化；而 IC 上我們量過最大的一次
（F6 GAT +0.0107）大概只值 1–2 個百分點。** 修這把尺不是「改做組合層」，
是讓年化這個量尺本身可用——IC 路線與組合路線都需要它。

## 1. 基準版（固定，不掃描）

| 項目 | 值 | 理由 |
|---|---|---|
| 配權 | **等權**（進場時等權，窗內自然漂移） | 不引入「分數大小可不可信」這個額外變因。分數加權留到模型定案後做對照組 |
| 買進成本 | **0.15%** | 法定牌告手續費 0.1425%，取整偏保守 |
| 賣出成本 | **0.45%** | 手續費 0.1425% ＋ 證交稅 0.30% = 0.4425%，取整偏保守 |
| 手續費折扣 | **不套用** | 券商折扣（常見 5–6 折）因人而異；基準版用未打折是更保守、不會高估績效的選擇 |
| 成交價 | 當日**收盤價** | 與訊號產生時點一致 |
| 主基準 | **等權 eligible 宇宙**（每日再平衡、不計成本） | 見 §7 第 ① 點：TWII 是基準錯配 |
| 次基準 | TWII（僅供脈絡，不單獨引用） | |

⚠️ **當沖稅率不適用**：5 日／每日再平衡策略是一般交易，賣出稅率 0.30% 而非當沖的 0.15%。
已於 2026-08-01 掃過全部四個成本定義點（`baseline_common.PROTOCOL`、`scanner_engine.py`、
`sim_engine_v2.py`、`sim_engine_v3.py`），**全部為 0.0015 / 0.0045，無誤用**。

## 2. 掃描網格（240 組）

| 維度 | 值 | 說明 |
|---|---|---|
| 持股數 `N` | **10 / 25 / 50 / 100 / 224** | 224 ≈ 可交易宇宙 2,245 的前 10%（decile） |
| 緩衝倍數 `k` | **1.0 / 1.3 / 1.5 / 2.0** | `k=1.0` 即無緩衝（現行行為）。持股跌出 `rank > k×N` 才賣 |
| 再平衡頻率 | **1 / 3 / 5 / 20** 交易日 | |
| 流動性門檻 | **無 / 前 2/3 / 前 1/3** | 以近 20 日成交金額中位數的當日百分位計 |

### 緩衝（banding）的精確定義

指數編製的標準作法（Russell、S&P 皆用此類規則）：

```
每個再平衡日 d：
  1. 賣出：現有持股中 rank(d) > k×N 者
  2. 買進：從 rank(d) ≤ N 且未持有者中，依 rank 由小到大補滿到 N 檔
```

`keep ⊆ holdings` 且 `|holdings| = N`，故候選永遠足夠（證明見 `portfolio_lab.py` docstring）。

## 5b. 定位變更（2026-08-01）：這份規格會成為接班系統的規格

使用者決定 **`scanner.py` 的訊號系統跟 V6.1 一起退役**，由組合建構層接班
（理由：現行的「複合分數 ≥70 就 BUY」是上課前自己想的粗糙策略）。

→ **本文件不再只是「讓年化可比的量尺」，而是接班系統的設計基礎。**
這提高了它的標準：以下幾件回測**沒有模型**的東西，在上線前必須補上。

| 缺口 | 影響 |
|---|---|
| **整張（1,000 股）交易的資金門檻** | 實測等權買滿各 1 張的最低資金：**N=10 約 65 萬、N=25 約 205 萬、N=50 約 365 萬、N=224 約 1,437 萬**（2026-06-02 的 `v2_kg` 排名 × 收盤價）。而 Mamba 家族是**分散型訊號、N 越大越好**——**與資金門檻方向相反**。盤中零股可買碎股，但流動性與價差較差 |
| **漲跌停 / 停牌的可成交性** | 回測用收盤價成交、不檢查漲停鎖死（買不到）或跌停（賣不掉），而 `prices_raw` 根本沒有這四類狀態欄位 |
| **實際持倉同步與部分成交** | 回測假設下單即全額成交 |
| **權重漂移的再平衡** | 回測是「進場等權、窗內漂移」，實務要決定漂移到什麼程度才調整 |

⚠️ **在「優先級 1 外部效度」通過之前，不要開始建接班系統**——
目前所有結論都來自單一 2.3 年多頭窗口，拿一個可能不成立的規格去蓋生產系統是本末倒置。

## 6. 已知限制（誠實揭露）

1. **無滑價模型**。成本只有手續費與稅。檢核表原文說「對 Top50 這種相對大型／流動股
   為主的組合，滑價影響通常不大」——**那個前提我們從未驗證過**，而 D1 分層診斷顯示
   IC 是被小型股墊高的（流動性小/中/大 = +0.140 / +0.100 / +0.0705）。
   → 流動性門檻這個維度就是為了量這件事。
2. **無漲跌停／停牌的可成交性檢查**。台股有 ±10% 限制，漲停鎖死買不到、跌停賣不掉，
   而 `prices_raw` **根本沒有這四類交易狀態欄位**（已記於 CLAUDE.md 待辦）。
   → 回測會系統性偏樂觀，程度未量化。
3. **存活者偏差未量化**（沿用方向二既有揭露）。
4. **單股權重上限 5% 不強制執行，只做觀察**。等權進場時每檔 `1/N`：N≥20 時該上限
   不會綁定；N<20 時 `1/N > 5%` 使該上限在數學上不可能成立。
   → 改為輸出「觀察到的最大單股權重」，讓漂移與異常看得見，而不是設一個假的約束。
5. **跨 N 比較要看 Sharpe/IR，不是年化**。N 變大同時改變報酬與波動，
   只看年化會系統性偏好集中組合。

### 以下為原始提案內容（保留，供追溯「為什麼換」）

第一批結果（`docs/portfolio-lab-results-2026-08-01.md`）暴露兩個規格層級的問題。
依 §5.4，任何修訂都必須記錄「為什麼換」，且**不得在看到數字後偷偷替換**——

### 提案 A：修訂「貼近實際操作」headline（**這是我凍結規格時的設計失誤**）

| | v1.0（現行） | v1.1 提案 |
|---|---|---|
| 再平衡頻率 | 每日 | **20 日** |
| 其餘 | N=25、k=1.5、流動性前 1/3 | 不變 |

**理由**：使用者說的是「**每天看 dashboard**」，我把它等同於「**每天換股**」——
這兩件事不一樣，是我在凍結時混為一談。而實測顯示每日再平衡在 Ridge 是 −16.3%、
GBDT 是 −31.6%，根因是**模型的 Top50 名單隔天只留存 34–47%**（見結果文件 §3），
不是成本假設太嚴。「每天看、但不每天換」對應的是「高頻檢查 + 低頻換手」，
在現行網格裡最接近的是 20 日再平衡 + 緩衝。

⚠️ 這個修訂**是在看到數字之後提出的**，所以它不能被當成「v1.0 的結論」。
採用後所有模型都要在 v1.1 下重跑，且新舊數字不得混用。

### 提案 B：新增「分數平滑」維度（探索性結果支持）

在排名之前先對分數做 `w` 日移動平均，`w ∈ {1, 3, 5, 10}`（`w=1` 即現行）。

**理由**：診斷顯示換手的根因是**分數本身日間噪音大**（排名 lag1 自相關 0.70–0.79，
但 Top50 隔日留存只有 34–47%）。緩衝治的是症狀，平滑治的是根因。
探索性測試顯示它把換手砍到約一半、Sharpe 一致上升（兩個模型同向）。

⚠️ 同樣是**看到數據後才加的維度**，必須重新 pre-register 並對所有模型重跑，
不得併入 v1.0 的比較。

### 提案 C：再平衡頻率補上 10 日（**使用者要求，已直接生效**）

網格 `1 / 3 / 5 / 20` → **`1 / 3 / 5 / 10 / 20`**（240 → 300 組）。

**理由**（使用者 2026-08-01）：「之後在跑實際測試的時候可能 5 天 10 天的也都還是要測試，
不能只有 20 天的。」原網格從 5 日直接跳到 20 日，中間缺一格，而實測顯示 10 日確實
落在有意義的位置（`v2_kg`：5 日 +9.7% → **10 日 +19.3%** → 20 日 +26.1%）。

這是**擴充**不是**替換**：不改任何既有取值、不改 headline 定義，
既有結果仍然可比，因此直接生效、不需等待確認。

### 提案 D：新增「大盤區間」的條件式報告（依 C 的檢定經驗）

前後半切分**測不到趨勢混淆**（兩半都是多頭：+14.2% / +15.9%）。
改依「等權宇宙過去 20 日累積報酬」的正負分上升／下跌段報告，
才問得出「這個設定是不是只在多頭有用」。已在結果文件 §7c 實作，
建議納入 `portfolio_lab` 的標準輸出。
